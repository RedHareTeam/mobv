## 00. 앱 이름 변경 — Chemeet → Mobv

기존 이름 Chemeet과 동일한 서비스가 이미 존재해 출시 시 식별성 문제 우려. 아래 4가지 기준으로 검토 후 Mobv로 확정.

| 체크 항목 | 결과 |
| --- | --- |
| 플레이스토어 | ✅ 동일 이름 앱 없음 |
| 앱스토어 | ✅ 동일 이름 앱 없음 |
| 도메인 (.kr) | ✅ mobv.kr 등록 가능 |
| 인스타그램 | ✅ @mobv 사용 가능 |

'모이다(모)' + 'Move(브)'의 합성. 이름 자체보다 슬로건으로 서비스 정체성을 전달하는 전략.

### 추가 후보 검토

| 이름 | 발음 | 컨셉 | 평가 |
| --- | --- | --- | --- |
| **Venn** | 벤 | 벤다이어그램 자체를 이름으로 | 컨셉 전달력 최고. 단, 수학 용어라 검색 시 교육 콘텐츠에 묻힐 수 있음 |
| **Meeve** | 미브 | Meet + Move 합성 | 발음 자연스럽고 검색 독립성 확보 가능. 의미는 설명 듣고 알게 됨 |
| **Moove** | 무브 | Move의 변형 | 발음 직관적이나 'Move 오타' 느낌. move 검색에 묻힐 가능성 높음 |
| **Muve** | 뮤브 | Move 변형, 짧고 깔끔 | Moove보다 독립적이나 발음 혼동 가능 (뮤브? 무브?) |
| **Movin** | 모빈 | Moving 축약 | 친근한 느낌이나 사람 이름처럼 들려 개성 약함 |
| **Movim** | 모빔 | Move + 모임 합성 | 짧고 발음 괜찮음. 검색 독립성 확보 가능 |

### 결론

 **Meeve**가 발음과 검색 독립성 면에서 그나마 경쟁력 있으나, Mobv 대비 개성이 약하고 "이미 있는 서비스 같은" 느낌을 줌. **Mobv**가 현재 기준 가장 합리적인 선택.

## 03. 서비스 포지셔닝

| 서비스 | 방식 | 한계 |
| --- | --- | --- |
| 만나중간에서 / 위밋플레이스 | 좌표 중간점 계산 | 선호 지역 반영 없음 |
| 노라보자 | 날짜 조율 | 장소 기능 없음 |
| **Mobv** | **선호 범위 교집합 + 날짜 조율 + 장소 추천** | ✅ 세 가지 동시 해결 |

'어디가 가장 가기 편한가?'가 아니라 **'어디가 모두가 괜찮은 곳인가?'** 를 해결.

## 04. 핵심 개념

### 원 그리기 = 만나도 괜찮은 범위

- 출발지 기반 이동 범위가 아니라, 각자 만나도 괜찮다고 생각하는 지역을 원으로 자유롭게 표시
- UI 문구: **"이 범위 안이라면 만나도 괜찮아요"** (선호한 한 곳이 아닌 협상 가능한 범위)
- 기본 반경 2km 자동 제공 → 사용자가 자유롭게 조정

### 교집합 = 모두가 허용한 구역

- 각자 그린 원이 겹치는 영역 = 모두가 괜찮다고 한 지역
- 교집합 중심 영역 기준으로 장소 추천
- 교집합 없을 때: 실패가 아니라 정보 — "겹치는 지역이 없어요. 조금 더 넓게 선택해보세요."

## 05. 변경사항

### 제거

| 항목 | 이유 |
| --- | --- |
| 카카오톡 파일 업로드 | 진입장벽 높음, 핵심 UX 아님 |
| 대화 분석 (GPT-4o-mini) | 업로드 제거로 불필요 |
| 친밀도 점수 기반 반경 확장 | 대화 분석 제거로 함께 제거 |

### 추가

| 항목 | 내용 |
| --- | --- |
| 날짜 조율 기능 | 각자 가능한 날짜 다중 선택 + 시간대 선택 → 교집합 자동 추출 → 방장 확정 |
| 결과 공유 기능 | 추천 장소 10개를 웹 링크로 공유 (앱 없이도 접근 가능) |

### 개선

| 항목 | 내용 |
| --- | --- |
| 교집합 없을 때 | 중간지점 fallback 제거 → 범위 재조정 유도 |
| 전원 완료 시 자동 추천 | 모든 멤버가 원을 그리면 자동으로 장소 추천 |
| 장소 추천 API | 카카오 로컬 → Google Places 검토 (사진·평점·영업시간) |
| 추천 검색 기준 | 교집합 내 지하철역 기준 검색 (중심 좌표가 주택가일 때 보완) |

## 06. 사용자 플로우

날짜 조율과 원 그리기는 서로 독립적 — 순서 무관, 동시 접속 불필요.

| 단계 | 내용 |
| --- | --- |
| STEP 1 | 방 만들기 + 카테고리 선택 + 멤버 초대 (2~5명, 추천 3~4명) |
| STEP 2 | 각자 ① 날짜·시간대 선택 ② 선호 범위 원 그리기 (완전 비동기) |
| STEP 3 | 날짜 전원 입력 완료 → 방장이 최종 날짜 확정 |
| STEP 4 | 원 전원 입력 완료 → 장소 10개 자동 추천 |
| STEP 5 | 결과 웹 링크 공유 (카카오톡 등) |
| STEP 6 | 장소 확정 → 히스토리 저장 |

**Firestore 구조**

```
rooms          └ roomId (allDatesCompleted, allCirclesCompleted 등 상태)
members        └ uid
availabilities └ uid (날짜/시간대)
circles        └ uid (선호 범위 원)
```

## 09. 보안 체크리스트

Firestore Rules가 최우선 — Rules가 비어 있으면 어떤 로그인 방식을 쓰든 보안적으로 의미 없음.

**P0 (출시 전 필수)**

| 항목 | 내용 |
| --- | --- |
| Firestore Security Rules | 본인 데이터만 읽기/쓰기 가능하도록 설정 |
| Firebase Auth | Google 로그인 기반 인증 적용 |
| 계정 삭제 기능 | 플레이스토어 심사에서 확인하는 항목 |
| 개인정보처리방침 | 수집 항목·목적·제3자 제공 명시 |
| 백엔드 토큰 검증 | Flask API 엔드포인트에 Firebase ID Token 검증 추가 |

**P1 (권장)**

| 항목 | 내용 |
| --- | --- |
| Firebase App Check | 봇 차단 |
| Rate Limit | API 호출 제한 |

## 11. 출시 전 검증 계획

친구 5~10명 대상, 실제 약속 잡기에 사용해보는 소규모 베타 테스트.

- 날짜 조율 기능을 실제로 사용하는가, 그냥 카톡으로 정하는가
- 원 그리기 기능을 실제로 사용하는가
- 교집합이 자주 안 생겨서 불편한가, 혹은 잘 작동하는가
- 결과 공유 링크가 카톡 등으로 잘 전파되는가
