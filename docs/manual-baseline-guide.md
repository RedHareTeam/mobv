# 수작업 기준선 측정 안내

이 작업은 **정답 맞히기 시험이 아니다.** 처음 보는 가상 VOC를 사람이 정책표에 따라 분류할 때 걸리는 시간을 기록한다. 헷갈린 항목이 생기는 것도 측정 결과의 일부다. AI 결과와 정답 파일은 보지 않는다.

## 시작 전에 기억할 네 가지

| 질문 | 고르는 값 | 빠른 기준 |
| --- | --- | --- |
| 무슨 종류인가? | `BUG`, `USABILITY`, `REQUEST`, `ACCOUNT`, `POLICY`, `INFORMATION`, `ETC` | 작동 실패는 BUG, 사용하기 어려움은 USABILITY, 새 기능 요구는 REQUEST, 계정·인증 절차는 ACCOUNT, 개인정보·권한은 POLICY, 사용법 질문은 INFORMATION, 근거 부족은 ETC |
| 어느 기능인가? | `AUTH`, `APPOINTMENT`, `DATE_COORDINATION`, `MAP_LOCATION`, `RECOMMENDATION`, `VOTING`, `HISTORY`, `COMMON` | 로그인·가입 / 약속·초대 / 날짜·시간 / 지도·위치 / 장소 추천 / 장소 투표 / 기록·메모 / 앱 전체·불명확 |
| 얼마나 급한가? | `P0`, `P1`, `P2`, `P3` | 다른 사람 정보 노출은 P0, 핵심 흐름 차단·데이터 유실은 P1, 일부 오류·우회 가능은 P2, 문의·제안·경미한 사용성은 P3 |
| 누가 먼저 볼까? | `DEVELOPMENT`, `DESIGN_UX`, `PRODUCT`, `OPERATIONS`, `POLICY_SECURITY`, `NEEDS_TRIAGE` | 기술 오류 / 화면·문구 / 기능 기획 / 이용 안내·계정 운영 / 개인정보·권한 / 정보 부족 |

한 문장에서 둘 이상이 섞이면 **사용자 피해가 가장 큰 문제 하나**를 대표로 고른다. 판단 근거가 부족하면 `ETC`와 `NEEDS_TRIAGE`를 사용할 수 있다. 확신이 없는 이유는 마지막 `어려웠던 판단/근거` 칸에 짧게 적는다. 모르는 항목 때문에 오래 멈추기보다 현재 정보로 최선의 판단을 기록한다.

## 중단한 3건으로 연습하기

이전 입력의 첫 3건은 이미 보았으므로 **새 기준선 측정에는 쓰지 않는다.** 아래는 정책을 적용하는 연습 예시이며, 여러 해석이 가능한 부분은 메모로 남길 수 있다.

| 사례 | 생각하는 순서 |
| --- | --- |
| `BASE-001` 로그인 화면이 계속 로딩됨 | 기능이 작동하지 않으므로 `BUG` → 로그인은 `AUTH` → 앱 진입이 막혀 `P1` → 기술 오류이므로 `DEVELOPMENT`. 입력한 판단에 근거가 있다. |
| `BASE-002` 인증 링크 유효기간 질문 | 계정·인증 절차에 관한 질문이므로 `ACCOUNT`와 `AUTH`가 자연스럽다. 급한 장애 신고가 아니어서 `P3`, 안내 담당인 `OPERATIONS`를 고를 수 있다. `INFORMATION`과의 경계가 헷갈렸다면 그 점을 메모한다. |
| `BASE-003` 어두운 화면 설정을 원함 | 현재 없는 설정을 원하므로 `REQUEST` → 앱 전반의 화면 설정이므로 `COMMON` → 일반 기능 제안인 `P3` → 기능 범위를 결정하는 `PRODUCT`. |

이 연습의 목적은 코드의 뜻을 익히는 것이다. 새 30건의 개별 판단을 AI에게 물어보면서 측정하지 않는다.

## 측정 방법

1. 위 표와 [분류 정책](classification-policy.md)을 먼저 읽고 코드의 뜻을 익힌다. 읽는 시간은 측정에 넣지 않는다.
2. 프로젝트 폴더에서 `python scripts/manual_baseline.py`를 실행한다. 준비 화면에서 Enter를 누를 때부터 시간이 측정된다.
3. 30건 각각에 유형·제품 영역·우선순위·담당을 입력한다. 헷갈린 내용은 마지막 칸에 적는다. 정답이나 AI 결과를 검색하지 않는다. 각 답을 입력하기 직전에 해당 항목의 짧은 기준이 표시되며, 기준을 보는 시간도 측정에 포함한다.
4. 30건을 모두 끝내면 `output/manual_baseline.csv`와 `output/manual_baseline.json`이 저장된다. 중간에 종료하면 불완전한 결과는 저장하지 않는다.

처음 시도에서 본 `BASE-001`~`BASE-003`은 새 기준선에서 제외했다. 새 측정 입력은 정답이 없는 별도 파일 `data/manual_baseline_v2_voc.csv`다. 이 파일을 미리 열어보지 말고 도구에 한 건씩 표시되는 문장으로 판단한다. 그래야 처음 보는 문장을 처리하는 시간이 남는다.
