# Day 3 작업 메모 — 2026-10-19

## 구현 및 실행

- 입력 CSV 전체를 먼저 검증하고 처리용 복사본만 정규화한다. 원본은 수정하지 않는다.
- 이메일·휴대전화 형식을 마스킹한 후 분류한다. 정답 CSV는 분류 경로에 포함되지 않는다.
- 결정적 규칙 분류 초안, 규칙 검증, 검토 큐 분리, 실행 로그를 구현했다.
- 개발용 가상 VOC 30건을 처리했다: 성공 30건, 실패 0건, 사람 검토 큐 17건.
- 개발 정답과 `rule_category`, `product_area`, `rule_priority`, `rule_owner`, `needs_review`를 비교했을 때 각 30/30건 일치했다. 개발 세트에 맞춰 규칙을 조정한 값이며 AI 성능이나 독립 평가 결과가 아니다. `review_flags`의 완전 일치는 이 수치에 포함하지 않았다.
- 테스트 4개 통과: 개발 세트 산출물·마스킹, 잘못된 날짜의 출력 차단, 개인정보 노출·프롬프트 인젝션 검토, 연락처 마스킹.

## 경계 판단

- 한 초대 코드에서 참여가 실패하는 경우는 전체 약속 흐름 장애라고 단정하지 않고 P2로 둔다. 로그인 진입 실패, 저장 데이터 유실, 잘못된 확정, 투표 중복 집계는 P1로 검토한다.
- 개인정보 **노출**은 P0, 권한 없는 확정은 P1이다. 정보 보관 기간을 묻는 문의는 `PRIVACY_SECURITY` 검토 플래그를 붙이되 문의 자체를 P1 사고로 올리지 않는다. 이는 [분류 정책](classification-policy.md)의 우선순위 사례와 개발 정답에 따른 해석이다.
- 여러 문제가 있는 `DEV-030`은 추천 상세 화면 실패보다 방문 메모 유실의 영향이 커서 제품 영역을 `HISTORY`로 선택한다.
- `LOW_CONFIDENCE` 등 초안의 플래그는 개발 정답 플래그와 완전히 같다고 가정하지 않는다. 모델 연결 이후 별도 검토가 필요하다.

## 남은 일

- 실제 사람이 `scripts/manual_baseline.py`로 30건을 판단해야 수작업 시간 기준선이 생긴다. 현재 기록된 시간 절감률은 없다.
- AI 모델 어댑터와 구조화 출력 검증·재시도, 사람 승인·수정 저장, 대시보드·주간 보고서는 후속 작업이다.
- `evaluation_gold.csv`는 읽거나 초안 규칙 조정에 사용하지 않았다. 독립 평가는 구현을 고정한 뒤 수행한다.
