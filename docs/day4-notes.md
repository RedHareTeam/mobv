# Day 4 작업 메모 — 2026-10-19

## 구현

- [공식 OpenAI 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)의 Responses API `text.format` JSON 스키마 방식으로 모델 어댑터를 구현했다. Python 표준 라이브러리를 사용해 SDK 설치가 필요 없다.
- 실제 모델 모드는 `--engine openai`로 명시한다. 프로젝트 폴더의 `.env` 또는 셸 환경 변수에서 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 읽는다. `--model`로 모델을 직접 지정할 수도 있다. 키가 없으면 시작 전에 오류를 내고 기존 규칙 초안 결과로 대체하지 않는다.
- 사용자 VOC는 이메일·휴대전화 형식을 가린 뒤 API에 전송한다. 응답 저장은 `store=false`로 요청한다.
- 모델 응답의 필드·허용값·VOC ID·우선순위별 SLA를 로컬에서 재검증한다. 응답 거절·미완료·형식 오류·일시적 API 오류를 구분하고, 재시도 후 실패한 건은 검토 큐와 실행 로그에 남긴다.
- 모델이 P0 개인정보 노출을 낮게 판단해도 운영 규칙이 우선순위를 P0으로 보정하고 AI 최초값과 규칙 보정값을 각각 기록한다.
- 답이 없는 별도 가상 VOC 30건을 `data/manual_baseline_voc.csv`에 만들고 수작업 측정 도구의 기본 입력으로 바꿨다.

## 검증과 현재 한계

- API 응답을 흉내 낸 테스트를 포함해 9개 테스트가 통과했다. 마스킹, 엄격한 스키마, 잘못된 응답 재시도·검토 큐, 긴급도 보정을 확인했다.
- 2026-10-19에 `gpt-6-luna`로 개발용 가상 VOC 1건 연결 시험을 완료했다. 이어 개발 세트 30건을 실제 API로 처리해 성공 30건, 실패 0건, 사람 검토 17건, 규칙 보정 1건을 기록했다. 전체 처리 시간은 131.387초였으며 결과는 `output/openai/`에 있다.
- 이 실행은 API 연결과 출력 흐름을 확인한 것이다. AI 분류 정확도와 API 비용은 아직 평가하지 않았다. 개발 세트 결과를 독립 평가 성능으로 해석하지 않는다.
- 새 수작업 입력은 CSV 형식과 개발 세트와의 ID 분리를 확인했다. 사람이 직접 분류하기 전까지 수작업 기준선은 없다.
- 최종 평가 정답은 열거나 프롬프트·규칙 조정에 사용하지 않았다.
